# MCP란 무엇이고, REA를 Codex에 어떻게 연결하나요?

2026-10-29 기준. Windows의 Codex 데스크톱 앱과 이미 설치한 REA 6.8.0을 대상으로 합니다. 이 문서는 연결 절차를 설명하며, 작성 과정에서 실제 MCP 설정을 변경하거나 연결 성공을 확인하지는 않았습니다.

## 1. MCP는 기능인가요, 기술인가요?

**MCP(Model Context Protocol)는 AI 앱과 외부 도구·데이터를 연결하는 통신 규약입니다.** 하나의 분석 프로그램 이름이나 AI 모델이 아니라, 서로 요청과 결과를 주고받는 방식을 정한 기술입니다.

이 경우 각 역할은 다음과 같습니다.

| 구성 요소 | 역할 |
| --- | --- |
| Codex | 사용자와 대화하고 AI가 사용할 도구 연결을 관리하는 앱 |
| AI | 질문에 맞는 도구와 입력을 선택하고 결과를 해석 |
| REA MCP 서버 | 사용할 수 있는 REA 도구 목록과 입력 형식을 제공하고, 요청된 분석을 수행 |
| 게임 복사본 | 분석 대상 파일. MCP 서버와는 별개 |

REA는 로컬 프로세스의 표준 입출력인 **stdio**를 통해 연결할 수 있습니다. 이 방식에서는 Codex가 REA 서버를 실행하고 메시지를 주고받으므로, 사용자가 별도 웹 서버나 포트를 열 필요가 없습니다.

```text
사용자: “FTK의 피해량 계산을 조사해 줘”
    ↓
Codex의 AI가 REA 분석 도구와 입력을 선택
    ↓ MCP 메시지
로컬 REA 서버가 지정한 DLL을 정적으로 분석
    ↓ 분석 결과·Evidence·검사 범위와 한계
AI가 결과를 설명하고 필요한 부분을 추가 조회
```

REA의 정적 분석은 로컬에서 수행됩니다. 다만 반환된 분석 결과를 AI가 해석할 때는 사용하는 모델 서비스의 데이터 정책이 적용됩니다.

## 2. 지금 방식과 무엇이 달라지나요?

지금도 AI가 터미널을 통해 REA CLI를 실행할 수 있습니다. MCP 연결은 AI가 REA의 전용 도구를 직접 사용하게 만드는 추가 경로입니다.

| 항목 | CLI 사용 | MCP 연결 |
| --- | --- | --- |
| 요청 | 터미널 명령과 옵션 | 등록된 도구와 구조화된 입력 |
| 결과 | 터미널 출력 또는 JSON 파일 | 도구 호출 결과로 전달 |
| 후속 조사 | 파일과 명령을 통해 연결 | 서버가 지원하는 세션·보관된 Evidence 조회 활용 |
| 분석 기능 | 설치된 REA와 분석기에 따름 | 설치된 REA와 분석기에 따름 |

**MCP를 연결한다고 디컴파일 능력이나 지원 형식이 늘어나는 것은 아닙니다.** 전체 분석의 용량 제한도 그대로입니다. FTK는 앞서 성공한 것처럼 타입·메서드 범위를 좁혀 조사합니다.

또한 REA 작업 지침인 스킬 설치와 MCP 연결은 별개입니다. 스킬은 조사 방법을 안내하고, MCP는 실제 도구 호출을 연결합니다.

## 3. 현재 환경에서 필요한 준비

이미 다음 단계는 완료했습니다.

- Node.js `24.22.1`과 npm 실행 확인
- A 방식인 글로벌 패키지로 REA `6.8.0` 설치
- `Assembly-CSharp.dll`의 실제 관리 코드 분석 성공

따라서 소스 빌드인 B 방식이나 Ghidra·Java 설치를 추가로 진행할 필요는 없습니다. 이번에는 설치된 REA를 Codex에 등록합니다.

먼저 Codex의 기존 MCP 연결 또는 플러그인 목록에서 REA가 이미 연결되어 있는지 확인합니다. **REA 플러그인이 연결을 제공하고 있다면 아래 setup 등록을 중복 추가하지 마세요.** 이 문서의 진단 명령은 setup이 관리하는 등록을 기준으로 합니다.

## 4. 변경 계획 먼저 확인하기

사용자 PowerShell에서 실행합니다.

```powershell
Set-Location 'E:\GitHub\rea'
rea.cmd setup --client codex --dry-run
```

`--client codex`는 연결할 앱을 Codex로 한정하고, `--dry-run`은 파일을 쓰지 않고 계획만 보여줍니다. `--yes`는 사용하지 않습니다.

계획에서 다음을 확인합니다.

- 선택한 앱이 Codex인지
- 실행할 Node와 REA가 실제 설치된 경로를 가리키는지
- 수정할 설정 파일 경로와 백업 위치
- 함께 설치하거나 갱신할 REA 스킬의 경로
- 원하지 않는 분석기 설치가 포함되지 않았는지

Codex의 기본 사용자 설정은 `C:\Users\yudle\.codex\config.toml`입니다. 별도 `CODEX_HOME`을 사용하는 환경에서는 경로가 달라질 수 있으므로 **실제로 출력된 계획의 경로를 기준**으로 합니다. 설정 파일 전체를 복사해 공유할 필요는 없습니다.

## 5. 계획을 검토한 뒤 연결 적용하기

설정을 수정하기 전 Codex 작업을 저장하고 앱을 종료한 뒤, 별도의 PowerShell에서 실행합니다.

```powershell
rea.cmd setup --client codex
```

1. 표시되는 변경 계획을 확인합니다.
2. REA 스킬 설치·갱신이 포함되면 경로와 변경 내용을 확인합니다.
3. Hopper 같은 선택적 분석기 설치가 제안되면 이번 .NET 정적 분석에는 필요하지 않으므로 선택하지 않습니다.
4. 계획이 맞으면 설정 변경을 승인합니다.
5. 완료 메시지와 백업 경로를 보관합니다.

REA setup은 기존의 관련 없는 설정을 보존하고 설정 변경 전 백업을 생성합니다. 취소하면 적용하지 않습니다. 소스에서 직접 설정 파일을 편집하는 대신 setup 절차부터 사용하는 편이 간단합니다.

setup은 사용하는 Node와 REA 진입 파일을 직접 등록합니다. 연결한 설치를 나중에 삭제하거나 경로를 옮기면 등록도 다시 확인해야 합니다.

## 6. Codex를 다시 열고 실제 연결 확인하기

완료 안내에 따라 Codex 앱을 다시 실행합니다. 실행 중인 대화의 도구 목록이 설정 변경 즉시 갱신됐다고 가정하지 않습니다.

먼저 PowerShell에서 setup 등록 상태를 확인할 수 있습니다.

```powershell
rea.cmd doctor --client codex --format json
```

이 명령의 등록 진단과 **Codex에서 실제 도구 호출이 성공하는지**는 구분합니다. 사용하지 않는 네이티브 분석기가 준비되지 않았다는 안내만으로 .NET 정적 분석 연결 실패라고 판단하지 않습니다.

다시 연 Codex 대화에서 아래와 같이 요청하세요.

```text
REA MCP 도구가 연결되어 있는지 확인해 줘.
CLI로 대신 실행하지 말고, 연결된 REA의 inspect_managed_artifact 도구로
다음 DLL의 식별 정보만 정적으로 검사해 줘.

C:\Users\yudle\Documents\REA용\For The King\FTK_Data\Managed\Assembly-CSharp.dll

게임을 실행하거나 파일을 변경하지 말고,
가능하면 detail: summary로 결과와 검사 한계를 간단히 알려줘.
```

연결 성공 기준은 REA 도구가 실제로 표시되고, 그 도구의 MCP 호출로 대상 DLL의 결과가 반환되는 것입니다. CLI 호출 성공만으로 MCP 연결 성공이라고 보고하지 않습니다. 설치 버전이 제공하는 실제 도구 입력 형식을 따릅니다.

참고로 대상 DLL의 기존 SHA-256은 다음과 같습니다.

```text
8096783ec9d1dcd8635c99ba8d73b133d5b5afad440ba4ea3053cc86e96a0dac
```

## 7. 연결이 안 될 때

| 증상 | 다음 확인 |
| --- | --- |
| `rea.cmd`를 찾지 못함 | 새 PowerShell에서 글로벌 npm 설치 경로와 PATH 확인 |
| setup은 끝났지만 도구가 안 보임 | Codex를 재시작했는지, 실제 사용하는 설정 경로에 등록했는지 확인 |
| REA 플러그인으로 설치했는데 doctor에 등록이 없다고 나옴 | 플러그인 소유 연결은 doctor가 관리하지 않으므로 플러그인의 연결 상태 확인 |
| 도구 호출 전에 클라이언트가 승인을 요구하거나 거부함 | Codex 권한 정책의 문제인지 확인. 분석기 재설치로 해결하지 않음 |
| 특정 분석기만 준비되지 않음 | 요청한 .NET 정적 분석 도구에 실제로 필요한 의존성인지 확인 |
| 출력이 너무 큼 | MCP 요약과 보관된 Evidence 조회 사용, 검사할 타입 선택 |

같은 setup을 반복하거나 관련 없는 프로그램을 설치하기 전에 정확한 오류를 확인합니다. 등록 계획이나 진단을 공유할 때는 필요한 부분만 전달하세요.
