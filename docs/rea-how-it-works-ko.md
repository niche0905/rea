# REA는 어떤 원리로 동작하나요?

REA(Reverse Engineer Anything)는 **AI 에이전트가 프로그램 분석 도구를 사용하고, 그 결과를 근거로 기능의 동작 원리를 조사하도록 연결하는 로컬 도구**입니다. 소스 코드가 없는 프로그램도 실행 파일, 포함된 스크립트, 메타데이터, 실행 중 관찰 결과 등을 통해 분석합니다.

> 작성 기준: 2026-10-29, 로컬 저장소 커밋 `e79ad6ca8`의 문서와 구조. 실제 대상 프로그램을 분석하거나 분석 엔진을 실행해 검증한 문서는 아닙니다.

## 1. 전체 흐름

```text
사용자: “이 프로그램의 검색 기능은 어떻게 동작해?”
    ↓
AI 에이전트: 조사할 파일과 함수를 선택하고 REA 도구 호출
    ↓ MCP — AI가 외부 도구를 호출하는 연결 규약
REA: 대상 종류에 맞는 분석기·파일 판독기를 사용
    ↓
분석 결과 + 근거(Evidence) + 한계·미확인 사항 반환
    ↓
AI 에이전트: 근거를 해석하고 필요한 부분을 추가 조사하여 설명
```

터미널의 CLI로도 같은 공통 분석 흐름을 사용할 수 있습니다. AI 없이 개별 분석 명령을 실행하는 것도 가능합니다.

## 2. 실행 파일에서 어떻게 정보를 얻나요?

일반적인 네이티브 프로그램은 소스 코드가 기계어로 컴파일되어 있습니다. 분석 엔진은 기계어를 어셈블리 명령으로 해석하는 **디스어셈블**, 이를 C와 비슷한 의사코드로 표현하는 **디컴파일**을 수행합니다. 문자열, 함수 호출 관계, 참조 위치도 조사해 기능과 관련된 코드를 좁혀 갑니다.

REA는 Hopper·Ghidra·IDA 같은 분석 엔진에 작업을 요청하고, 결과를 공통 형식으로 전달합니다. 대상 형식에 따라서는 외부 엔진 없이 자체 파일 판독기로 정보를 읽습니다.

| 대상 | 주로 살펴보는 정보 | 분석 방식의 예 |
| --- | --- | --- |
| 네이티브 EXE·DLL | 함수, 어셈블리, 의사코드, 문자열, 참조 | Ghidra 등 외부 엔진 연동 |
| JavaScript·Electron | 모듈, import, 소스맵, IPC 연결 | 디렉터리·ASAR와 코드 구조 분석 |
| .NET 어셈블리 | 타입·메서드 메타데이터, CIL 명령 | 전용 정적 판독기 |
| 웹사이트 | 페이지 구조, 스크립트, 네트워크 관찰 | 브라우저 연동 |

**정적 분석**은 대상 코드를 실행하지 않고 파일을 읽는 방식이고, **동적 분석**은 실행 중인 상태나 동작을 관찰하는 방식입니다. REA에는 양쪽 도구가 있으며, 실제 실행·연결 여부와 필요한 권한은 선택한 도구에 따라 달라집니다.

## 3. AI와 REA의 역할은 어떻게 다른가요?

분석 엔진과 판독기가 코드·구조를 추출하고, REA가 호출·세션·결과 형식을 관리하며, AI가 다음 조사와 해석을 맡습니다. 저장소도 CLI/MCP 진입점 → 공통 작업 흐름 → 분석기 어댑터와 도메인 계약으로 역할을 나눕니다.

예를 들어 검색 기능을 조사할 때는 관련 문자열이나 모듈을 찾고, 해당 코드를 참조하는 함수와 호출 관계를 따라가며, 필요하면 실행 중 관찰로 설명을 확인합니다. 이 예시는 조사 방식의 설명이며 특정 프로그램에서 확인한 결과는 아닙니다.

REA의 Evidence는 결과의 출처와 한계를 추적하기 위한 근거입니다. “이 위치에 이런 명령이 있다”는 관찰과 “이 함수가 검색을 담당할 것이다”라는 추론을 구분하고, 확인되지 않은 부분을 남기는 것이 중요합니다.

## 4. 사용 전에 알아둘 한계

- **원래 소스 코드의 완전 복원은 보장되지 않습니다.** 컴파일 과정에서 주석·이름·타입 정보가 사라질 수 있고, 의사코드는 원본과 다릅니다. 난독화나 패킹도 분석을 어렵게 합니다.
- **지원 대상마다 준비물이 다릅니다.** 네이티브 분석에 쓰는 Ghidra·IDA는 직접 설치해야 하며, REA 저장소를 클론하는 것만으로 분석 환경이 완성되지는 않습니다.
- **Windows 지원은 분석기별로 확인해야 합니다.** 현재 문서의 Windows Ghidra P0는 실험적 읽기 전용 범위이며, 모든 형식·기능을 지원하지 않습니다. 상세 조건은 아래 가이드를 참고하세요.
- **로컬 분석과 AI 데이터 처리는 별개입니다.** REA는 대상을 로컬에서 분석하지만, 에이전트에 전달된 도구 결과는 사용하는 모델 서비스의 데이터 정책을 따릅니다.

처음 조사할 때는 대상 프로그램의 형식과 궁금한 기능 하나를 정한 뒤, 파일 구조·문자열·함수 관계부터 확인하면 분석 범위를 잡기 쉽습니다.
